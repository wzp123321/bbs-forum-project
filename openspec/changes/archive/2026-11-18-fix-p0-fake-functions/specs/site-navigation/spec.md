# Spec Delta

## Purpose

定义用户可见导航入口的可达性约束，保证页面上不出现点击后无法到达目标或落入 404 的菜单项。

## ADDED Requirements

### Requirement: 导航项必须可达

顶部导航展示的每一个菜单项 SHALL 指向一个已注册的路由。

- 未配置路径的菜单项 MUST NOT 渲染给用户（不得展示为可点击但无跳转）。
- 已配置路径但路由不存在的菜单项 MUST 在发布前被修正或移除。

#### Scenario: 空路径项不渲染

- **WHEN** 菜单配置中存在 path 为空字符串的项
- **THEN** 该菜单项不出现在页面顶部导航中

#### Scenario: 点击不落空

- **WHEN** 用户点击顶部任意可见菜单项
- **THEN** 页面跳转到该菜单声明的目标页面，不出现 404

### Requirement: 创作入口

「创作中心」下的入口 SHALL 指向已存在的发布页面。

- 「写文章」与「发话题」两个入口 MUST 都落到同一个可用发布页；当前数据模型没有「文章 / 话题」的区分字段，因此不做类型预选，两个入口只作为不同语义的快捷方式。
- 未登录用户点击创作入口 MUST 跳转登录页并在登录后回到发布页。

#### Scenario: 创作中心可用

- **WHEN** 已登录用户点击「创作中心 → 写文章」
- **THEN** 打开发布页

#### Scenario: 未登录被拦截

- **WHEN** 未登录用户点击创作入口
- **THEN** 跳转登录页，登录成功后返回发布页

### Requirement: 未知路径统一兜底

访问站内不存在的路径 SHALL 展示 404 页面，并给出返回首页的入口。

#### Scenario: 不存在路径

- **WHEN** 用户访问一个未注册的站内路径
- **THEN** 显示 404 页面，页面内可点击返回首页
