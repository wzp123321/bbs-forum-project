# Spec Delta

## Purpose

定义互动通知的生成、撤销、查询与已读规则，让被点赞、被评论、被回复、被关注的用户能获知并定位到具体内容。

## ADDED Requirements

### Requirement: 通知生成

系统 SHALL 在以下互动发生时给接收者生成一条通知：点赞帖子、评论帖子、回复评论、关注用户、系统公告。

- 通知 MUST 记录：接收者、触发者（系统公告为空）、类型、关联帖子、摘要文本、创建时间。
- 触发者与接收者是同一人时 MUST NOT 生成通知（自己赞自己不通知）。
- 撤销互动时对应的未读通知 MUST 一并删除：取消点赞删除点赞通知，取消关注删除关注通知；评论删除后其通知保留但跳转时提示内容已删除。
- 同一触发者对同一目标的同类通知 MUST 只有一条，重复触发不新增。
- 帖子不存在、被逻辑删除或状态异常时 MUST NOT 生成通知。

#### Scenario: 被点赞收到通知

- **WHEN** 用户 B 给用户 A 的帖子点赞
- **THEN** 用户 A 收到一条「B 赞了你的帖子」通知，且未读数 +1

#### Scenario: 取消点赞撤回通知

- **WHEN** 用户 B 取消刚才的点赞
- **THEN** 用户 A 的该条通知消失，未读数 -1

#### Scenario: 自己点赞不通知

- **WHEN** 用户 A 给自己的帖子点赞
- **THEN** 不产生任何通知

#### Scenario: 评论与回复区分

- **WHEN** 用户 B 在 A 的帖子下直接评论
- **THEN** A 收到「B 评论了你的帖子」通知
- **WHEN** 用户 C 回复 B 的评论
- **THEN** B 收到「C 回复了你的评论」通知，帖子作者 A 不收到该条回复通知

### Requirement: 通知查询

登录用户 SHALL 能查询自己的通知列表与未读数。

- 未读数接口 MUST 返回当前用户的未读通知条数，不返回他人数据。
- 列表 MUST 按创建时间倒序、分页返回，并携带触发者昵称头像与关联帖子标题。
- 支持按已读状态筛选：全部 / 未读。
- 未登录请求 MUST 被拒绝。

#### Scenario: 未读数准确

- **WHEN** 用户有 3 条未读通知，打开任意页面
- **THEN** 铃铛角标显示 3

#### Scenario: 未登录被拦截

- **WHEN** 未登录用户请求通知列表
- **THEN** 接口返回未认证，不返回任何通知数据

#### Scenario: 只看未读

- **WHEN** 用户选择「只看未读」
- **THEN** 返回结果中每条通知的已读标记均为未读

### Requirement: 通知已读

用户 SHALL 能将单条通知或全部通知标记为已读。

- 单条已读 MUST 只影响本人的通知；对他人通知的已读请求 MUST 被拒绝且不生效。
- 全部已读 MUST 只把当前用户的未读置为已读。
- 已读操作 MUST 幂等：重复标记不报错。

#### Scenario: 单条已读

- **WHEN** 用户点击一条未读通知
- **THEN** 该条变为已读，未读数减 1

#### Scenario: 全部已读

- **WHEN** 用户点击「全部已读」
- **THEN** 未读数归零，再次点击不报错

#### Scenario: 不能标记他人通知

- **WHEN** 用户 A 请求把用户 B 的通知标记为已读
- **THEN** 接口拒绝，用户 B 的通知状态不变
